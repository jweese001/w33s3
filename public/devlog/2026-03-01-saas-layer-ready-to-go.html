The SaaS Layer is Ready. The Infrastructure Isn't.

March 1, 2026

This week I merged and immediately reverted a 15-commit PR. On paper, that looks like a mistake. In practice, it's exactly how I wanted this to go.

What I Built

FlowBoard's SaaS layer is done. The feature branch includes:

  • Supabase integration for auth, Postgres, and cloud storage
  • A storage adapter pattern that preserves localStorage for local-only mode
  • React Router with landing page, login, dashboard, and protected editor routes
  • Stripe checkout and webhook edge functions
  • Pro feature gating with a clean hook interface
  • An onboarding wizard for first-run flows
  • Vercel deployment config with SPA routing

Forty-three tests pass. TypeScript is happy. The code works.

Why the Revert?

The code is ready. The infrastructure isn't. I haven't created the Supabase project, configured Stripe products, or set up environment variables in Vercel. Those are one-time setup tasks that I didn't want to interrupt the development flow to handle.

So the feature lives in its branch, fully implemented, waiting for deployment day. The main branch stays clean and deployable as a local-only tool.

The Storage Adapter Pattern

The most interesting technical decision was how to handle the dual-mode storage. FlowBoard needs to work completely offline with localStorage and sync to the cloud when authenticated. I didn't want to litter the codebase with conditionals.

The solution: a storage adapter interface that both implementations satisfy. At startup, the app uses the local adapter. When you authenticate, it swaps to the cloud adapter. The rest of the app doesn't know or care which one is active.

// One line changes everything
setAdapter(createCloudAdapter(supabase, userId));

The existing localStorage logic didn't change at all. It just got wrapped in an adapter that matches the same interface as the Supabase version.

Pro Gating Without Being Annoying

Feature gating is easy to get wrong. Too aggressive and it feels like the free version is broken. Too lenient and there's no reason to upgrade.

My approach: local-only mode has no restrictions at all. Pro gating only applies to authenticated cloud users on the free plan. The mental model is simple—if you're not using the cloud, you're not limited by cloud tiers.

The hook makes checking permissions trivial:

const { canUse, showUpgrade } = useProGate('advancedExport');
if (!canUse) return showUpgrade();

What's Next

Infrastructure setup is on the list for next week. Create the Supabase project, run the migration, configure Stripe products, set environment variables, deploy to Vercel, and flip the switch. The code is ready—it's just waiting for its home.

In the meantime, FlowBoard continues working exactly as it did before. That's the point. SaaS features should enhance what's already there, not break it while you're still figuring out the deployment story.
