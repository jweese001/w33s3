FlowBoard: When Auth State Fights React State

March 8, 2026

This week on FlowBoard was a masterclass in why authentication state and React state don't always play nice together. I implemented the password recovery flow for our SaaS version, and what seemed like a straightforward feature turned into a deep dive into Supabase's auth event system and React's rendering lifecycle.

The Problem

The password reset flow looked simple on paper: user clicks "Forgot password," receives an email, clicks the link, enters a new password, done. But the reset page kept getting stuck on "Updating password..." indefinitely. No error, no timeout, just an eternal spinner mocking my confidence.

The Root Cause

Supabase's updateUser() triggers authentication state changes that interfere with React's state updates. When you call await updateUser({ password }), Supabase fires auth events that React tries to process, but the component is in the middle of a state transition. The promise never resolves because the auth state change causes React to re-render, which disrupts the async operation.

Classic state management collision.

The Solution: Fire and Forget

The fix was counterintuitive: don't await the password update. Fire it off and immediately redirect:

// Don't await - Supabase auth events fight React state
supabase.auth.updateUser({ password: newPassword });

// Redirect after brief delay
setTimeout(() => {
    window.location.href = '/login?reset=success';
}, 500);

Using window.location.href instead of React Router's navigate() was key. It completely escapes React's state management, giving the browser a clean slate. The password update completes in the background while the user sees a success message on the login page.

Bonus Bug: Flash of Stale Content

While debugging auth, I also tracked down a project persistence bug. When loading cloud projects, users would briefly see demo nodes flash on screen before their actual project appeared. The cause? FlowBoard's store initialized with demo data, and the async project load hadn't completed yet.

The fix involved three changes:

  • Initialize the flow store with empty arrays instead of demo nodes
  • Add an isProjectLoaded flag to prevent auto-save from overwriting data
  • Clear the canvas synchronously before starting the async load

State management in cloud-synced applications is a different beast than local-only apps. Every operation needs guards against race conditions.

What's Next

With password recovery working, the auth system is nearly complete. Next up: Google OAuth sign-in and Stripe billing integration. FlowBoard is getting closer to its SaaS launch, one state management bug at a time.

The lesson this week: when auth state fights React state, sometimes the answer is to step outside React entirely. Not every problem needs a React solution.
